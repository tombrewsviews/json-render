# Example Dashboard

The example-dashboard is a Next.js 16 application that demonstrates the json-render library's capabilities for creating AI-generated dashboards and user interfaces. It provides a complete component catalog system with 16 cataloged UI components available for AI generation, data binding through JSON pointers, action handling, and an AI generation endpoint that streams UI definitions in real-time.

## Package Information

- **Package Name**: example-dashboard
- **Package Type**: npm
- **Language**: TypeScript
- **Installation**: This is an example application, typically used as a reference implementation
- **Package Manager**: pnpm

## Core Imports

The application provides a component registry and catalog for building AI-generated dashboards:

```typescript
// Import component registry
import componentRegistry from "./components/ui";

// Import catalog and component list
import { dashboardCatalog, componentList } from "./lib/catalog";
```

## Basic Usage

This application demonstrates how to build AI-generated dashboards with guardrails. The key pattern involves:

1. Defining a component catalog with Zod schemas
2. Streaming UI generation from natural language prompts
3. Rendering components dynamically from JSON definitions
4. Binding data through JSON pointer paths

```typescript
import { useUIStream } from "@json-render/react";
import { Renderer } from "@json-render/react";
import { dashboardCatalog } from "./lib/catalog";
import componentRegistry from "./components/ui";

// Stream UI generation from user prompt
const { tree, isStreaming, send } = useUIStream({
  api: "/api/generate",
});

// Send prompt to generate UI
await send("Show revenue metrics and recent transactions", {
  data: { analytics: { revenue: 50000 } },
});

// Render the generated UI
<Renderer tree={tree} registry={componentRegistry} />;
```

## Architecture

The example-dashboard is built around several key architectural patterns:

- **Component Catalog System**: 16 components are defined in a catalog with Zod schemas, providing guardrails for AI generation and ensuring type-safe component instantiation (TextField component exists in the registry but is not in the catalog)
- **Data Binding via JSON Pointers**: Components access and modify global state using JSON pointer paths (RFC 6901), enabling declarative data binding
- **Streaming UI Generation**: AI generates JSONL (JSON Lines) patches that progressively build a UI tree, allowing real-time rendering as components stream in
- **Provider-based State Management**: DataProvider manages global application data, ActionProvider handles action triggers, and VisibilityProvider controls conditional rendering

### AI Generation API

API endpoint for streaming AI-generated UI components using Claude Opus 4.5.

```typescript { .api }
// POST /api/generate
interface GenerateRequest {
  prompt: string;
  context?: {
    data: any;
  };
}

// Response: Streaming text (JSONL format)
// Each line is a JSON patch operation
interface JSONLPatch {
  op: "set" | "add";
  path: string;
  value: any;
}
```

## Data Model

The application uses a structured data model for analytics and form state:

```typescript { .api }
interface DashboardData {
  analytics: {
    revenue: number;
    growth: number;
    customers: number;
    orders: number;
    salesByRegion: Array<{
      label: string;
      value: number;
    }>;
    recentTransactions: Array<{
      id: string;
      customer: string;
      amount: number;
      status: string;
      date: string;
    }>;
  };
  form: {
    dateRange: string;
    region: string;
  };
}
```

Data is accessed using JSON pointer paths:
- `/analytics/revenue` - Access revenue value
- `/analytics/salesByRegion` - Access regional sales array
- `/form/dateRange` - Access and modify date range selection
